## Acceptance criteria and checks

| ID | Criterion | Check | Task |
| --- | --- | --- | --- |
| FR-1 | WHEN the owner runs sauvegarde.mjs on the VPS, THE SYSTEM SHALL write a verified consistent copy of the live database outside the daily rotation: integrity ok, row counts at least the live ones, a SHA-256 file beside it | sonni | t2 |
| FR-2 | THE backup, drill, check and report scripts SHALL leave the live database and its folder unchanged: no write, no -wal or -shm created next to it, no file deleted outside their own temporary folder | sonni | t1, t2, t3, t4 |
| FR-3 | WHEN the owner runs restauration.mjs --essai on a copy, THE SYSTEM SHALL restore it into a new temporary folder, report integrity, row counts, SHA-256, restore time and the copy's age, and remove that folder | sonni | t2 |
| FR-4 | WHEN the owner runs restauration.mjs --restaurer, THE SYSTEM SHALL refuse unless --confirmer is given, the SHA-256 file matches and Sonni is stopped, and SHALL move the current database files into a quarantine folder instead of deleting them | sonni | t2 |
| FR-5 | WHEN the owner runs controle-predeploiement.mjs on a copy, THE SYSTEM SHALL report from a private copy the price audit, ledger reconciliation and each pending order, stop and paid wake a restart would trigger | sonni | t3 |
| FR-6 | WHEN the pre-deployment check finds a blocking anomaly or a point to decide, THE SYSTEM SHALL exit with code 1; --accepter-a-decider SHALL lift points to decide only, never a blocking anomaly | sonni | t3 |
| FR-7 | THE pre-deployment check's predicted first-tick outcome of each pending order and each stop SHALL equal what the new broker does on the same data (tested against brokerTick) | sonni | t3 |
| FR-8 | WHEN the owner runs controle-apres-demarrage.mjs after a start, THE SYSTEM SHALL read the live database read-only and SHALL exit 1 on any rollback trigger: wrong build, no price since start, broker incident, rejected order, unusable position, Telegram backlog | sonni | t4 |
| FR-9 | WHEN envoi-telegram.mjs runs, THE SYSTEM SHALL send the given French report to the owner's chat with the configured bot token, which it SHALL never print or read from the command line | sonni | t4 |
| FR-10 | THE VPS guide SHALL give the owner, in French, the survey, the pre-audit on a copy, the deployment window pinned to the approved commit, post-start checks, the Telegram report, the observation window and the rollback | sonni | t5 |
| FR-11 | WHEN this tooling ships, THE SYSTEM SHALL keep Sonni's runtime code, configuration, schema, stored history and audit-prix.mjs output unchanged, with tests making no network call outside 127.0.0.1 and no paid call | sonni, types, money-lab, runtime, sonni-e2e | t1, t5 |
